# Internationalization (i18n) Guide

This document explains how the language localization system works and how to add or update content for any language.

---

## Overview

The site supports multiple languages using Astro's built-in i18n routing combined with a TypeScript translation layer. English is the default language and lives at the root path (`/`). Each additional language is served under its own URL prefix (e.g., Thai at `/th/`).

| Language | URL prefix | Status |
|---|---|---|
| English | `/` (no prefix) | Live |
| Thai | `/th/` | Live |

---

## Architecture

```

├── i18n/
│   ├── types.ts       ← TypeScript interface defining every translatable key
│   ├── en.ts          ← English string values

│   ├── utils.ts       ← Helper functions (getLang, useTranslations, etc.)
│   └── index.ts       ← Barrel export
├── pages/
│   ├── index.astro           ← English home  (/)
│   ├── company.astro         ← English about (/company)
│   ├── contact.astro         ← English contact (/contact)
│   ├── products/
│   │   ├── index.astro       ← English body armors (/products)
│   │   ├── ballistic-helmets/index.astro
│   │   └── ballistic-plates/index.astro
│   └── th/                   ← Thai page wrappers
│       ├── index.astro       ← Thai home (/th)
│       ├── company.astro
│       ├── contact.astro
│       └── products/
│           ├── index.astro
│           ├── ballistic-helmets/index.astro
│           └── ballistic-plates/index.astro
└── components/
    ├── Navbar.astro    ← lang-aware, functional EN/TH switcher
    ├── Footer.astro    ← lang-aware
    ├── Home.astro      ← lang-aware
    ├── Company.astro   ← lang-aware
    ├── ContactUs.astro ← lang-aware
    ├── Armour.astro    ← lang-aware
    ├── Helmet.astro    ← lang-aware
    ├── Plate.astro     ← lang-aware
    ├── StatSection.astro    ← lang-aware
    └── ContactSection.astro ← lang-aware
```

### How it works

1. Each page file in `src/pages/th/` passes `lang="th"` to `<Layout>` and the page component.
2. English page files pass nothing (default `"en"` is used).
3. Every lang-aware component calls `useTranslations(lang)` to get a typed `t()` function.
4. `t("some.key")` returns the value from either `en.ts` or `th.ts` depending on `lang`.
5. `Layout.astro` uses `lang` to set `<html lang="...">`, load the right font, and emit hreflang tags.
6. The Navbar language switcher uses `getAlternateLangUrl()` to compute the equivalent page in the other language.

## How to Update Translations for Existing Languages

### Editing English content

Open `src/i18n/en.ts` and update the value for any key:

```ts
// src/i18n/en.ts
"home.hero.title1": "Part of Every Mission.",
```

Change it to whatever new text is needed. The TypeScript compiler will flag the key if it does not exist in `types.ts`.

### Editing Thai content

Open `src/i18n/th.ts` and update the corresponding key:

```ts
// src/i18n/th.ts
"home.hero.title1": "ส่วนหนึ่งของทุกภารกิจ",
```

Keep the key name identical to the English file — only the value differs.

### Updating array content (cards, steps, options)

Some keys hold arrays of objects. Update every object in the array:

```ts
// src/i18n/th.ts
"home.cards": [
  {
    label: "เสื้อเกราะกันกระสุน",
    description: "...",
    buttonText: "สำรวจเสื้อเกราะ",
    bgColor: "bg-[#14375f]",
    link: "/th/products",
  },
  // ...
],
```

> **Note:** The `bgColor` and `link` fields inside `home.cards` are functional — they control appearance and navigation. Keep `bgColor` identical to English, and ensure `link` uses the `/th/` prefix for Thai.

## How to Add a New Language

Follow these steps to add a new language, using Japanese (`ja`) as an example.

### Step 1 — Register the locale in Astro config

Open `astro.config.mjs` and add the new locale code to the `locales` array:

```js
i18n: {
  defaultLocale: "en",
  locales: ["en", "th", "ja"],   // ← add "ja"
  routing: {
    prefixDefaultLocale: false,
    redirectToDefaultLocale: false,
  },
},
```

### Step 2 — Add the language type

Open `src/i18n/types.ts` and update the `Lang` union type:

```ts
export type Lang = "en" | "th" | "ja";
```

### Step 3 — Create the translation file

Create `src/i18n/ja.ts` by copying `src/i18n/en.ts` and translating all values:

```ts
// src/i18n/ja.ts
import type { Translations } from "./types";

export const ja: Translations = {
  "layout.skipToMain": "メインコンテンツへスキップ",
  "nav.home": "ホーム",
  "nav.products": "製品",
  // ... translate every key
};
```

Every key defined in `types.ts` must be present. TypeScript will show an error for any missing key.

### Step 4 — Register the translation in utils.ts

Open `src/i18n/utils.ts` and add the new language to the translations map:

```ts
import { en } from "./en";
import { th } from "./th";
import { ja } from "./ja";   // ← add import
import type { Lang, Translations } from "./types";

const translations: Record<Lang, Translations> = { en, th, ja };  // ← add ja
```

Also update `getLang` to recognise the new locale code:

```ts
export function getLang(currentLocale: string | undefined): Lang {
  if (currentLocale === "th") return "th";
  if (currentLocale === "ja") return "ja";  // ← add this line
  return "en";
}
```

### Step 5 — Export from the barrel

Open `src/i18n/index.ts` and add the export:

```ts
export { en } from "./en";
export { th } from "./th";
export { ja } from "./ja";   // ← add
export { getLang, useTranslations, getAlternateLangUrl, breadcrumbUrl } from "./utils";
export type { Lang, Translations } from "./types";
```

### Step 6 — Add font support (if needed)

If the new language requires a non-Latin font, open `src/layouts/Layout.astro` and add a conditional font load alongside the existing Thai one:

```astro
{lang === "th" && (
  <link
    href="https://fonts.googleapis.com/css2?family=Sarabun:wght@400;500;600;700&display=swap"
    rel="stylesheet"
  />
)}
{lang === "ja" && (
  <link
    href="https://fonts.googleapis.com/css2?family=Noto+Sans+JP:wght@400;500;600;700&display=swap"
    rel="stylesheet"
  />
)}
```

Then add a CSS override in `src/styles/global.css`:

```css
:root[lang="ja"] {
  --font-space:  "Noto Sans JP", sans-serif;
  --font-hanken: "Noto Sans JP", sans-serif;
}

:root[lang="ja"] h1,
:root[lang="ja"] h2,
:root[lang="ja"] h3 {
  line-height: 1.5;
}
```

### Step 7 — Update the Navbar language switcher

Open `src/components/Navbar.astro`. The switcher currently has two hardcoded links (EN and TH). Add a link for the new language in all three switcher locations (desktop bar, mega-menu sidebar, mobile panel):

```astro
<a href={enHref} class:list={["lang-link", { "is-active": lang === "en" }]}>
  {t("nav.langEn")}
</a>
<a href={thHref} class:list={["lang-link", { "is-active": lang === "th" }]}>
  {t("nav.langTh")}
</a>
<a href={jaHref} class:list={["lang-link", { "is-active": lang === "ja" }]}>
  {t("nav.langJa")}
</a>
```

Add `nav.langJa` to `types.ts` and to both `en.ts` and `th.ts`:

```ts
// types.ts — add to the nav section
"nav.langJa": string;

// en.ts
"nav.langJa": "日本語",

// th.ts
"nav.langJa": "日本語",
```

Also compute the Japanese href alongside the Thai one:

```astro
const jaHref = lang === "ja" ? currentPath : "/ja" + (currentPath === "/" ? "" : currentPath);
```

### Step 8 — Create the page files

Create a `src/pages/ja/` directory mirroring the English and Thai structures. There are 6 pages. Each file is a thin wrapper:

```astro
---
// src/pages/ja/index.astro
import Home from "@/components/Home.astro";
import Layout from "@/layouts/Layout.astro";
import "@/styles/global.css";

const title = "Ch.Paisarn — 高品質軍用装備";
const description = "...";
const keywords = "...";
---

<Layout title={title} description={description} keywords={keywords} lang="ja">
  <Home lang="ja" />
</Layout>
```

Create all six pages:

```
src/pages/ja/index.astro
src/pages/ja/company.astro
src/pages/ja/contact.astro
src/pages/ja/products/index.astro
src/pages/ja/products/ballistic-helmets/index.astro
src/pages/ja/products/ballistic-plates/index.astro
```

### Step 9 — Update the `getAlternateLangUrl` utility

The current function handles only `"en"` and `"th"`. For a third language, update `src/i18n/utils.ts`:

```ts
export function getAlternateLangUrl(pathname: string, currentLang: Lang): string {
  // Strip any existing lang prefix
  const stripped = pathname.replace(/^\/(th|ja)/, "") || "/";

  if (currentLang === "en") return "/th" + (stripped === "/" ? "" : stripped); // default alternate
  return stripped; // return to English for any non-English lang
}
```

For a multi-language switcher where each language button always links to the correct path, compute all hrefs in Navbar:

```astro
const enPath = currentPath.replace(/^\/(th|ja)/, "") || "/";
const enHref = enPath;
const thHref = "/th" + (enPath === "/" ? "" : enPath);
const jaHref = "/ja" + (enPath === "/" ? "" : enPath);
```

### Step 10 — Verify the build

```bash
npm run build
```

The output should include your new language pages:

```
/ja/index.html
/ja/company/index.html
/ja/contact/index.html
/ja/products/index.html
/ja/products/ballistic-helmets/index.html
/ja/products/ballistic-plates/index.html
```

Check `dist/sitemap-0.xml` to confirm all new URLs are present.

## Common mistakes

**Missing translation key** — TypeScript will show a red underline. Add the key to `types.ts` first, then to every language file.

**Array key out of sync** — Keys like `home.cards` are arrays. If you add an item to the English array, add a matching item at the same index in every other language file.

**Forgetting the `/th/` prefix in card links** — The `home.cards` array in `th.ts` has `link: "/th/products"`. If you add a new card with a link, use the language-specific prefix.

**Font not loading for Thai** — The Sarabun font is only loaded when `lang="th"` is passed to `Layout`. Make sure Thai page files pass `lang="th"` to `<Layout>`.
